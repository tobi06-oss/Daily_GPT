# Phase 1 설계 결정 및 추가 요구사항 검토

## 유지한 원칙
- GPT 독립 시안: Today / 달력 / 일기 / 빠른 입력을 기존 레이아웃 안에서 확장
- 로그인, Supabase, 서버 동기화, 알림, ICS는 Phase 1에서 제외
- 나눔스퀘어, 크림·세이지·코랄 팔레트, 짧고 부드러운 안내 문구
- 기존 `lifeplanner.v1` 로컬 데이터의 필드를 그대로 두고 `goals`, `goal_checks`, `sleep_logs`, `user_settings` 필드만 추가
- 기록 ID와 날짜는 로컬에서 생성, 목표·수면 항목에는 `created_at`, `updated_at`, `deleted_at`, `rev` 포함

## 이번 확장안에서 구현한 방향
1. Today: 시간대 인사, 진행 중/다음 일정 남은 시간, 일곱 날짜 선택, 할 일 진행도
2. 일기: 날짜별 순환 질문, 2일 이상 연속 기록, 7일 전·한 달 전·1년 전 기록, 저녁 요약
3. 주간 목표: 1~7회 등록, 일~토 체크, 현재 및 과거 날짜 체크, 목표 달성·초과 표시, Quick Capture에서 주 N회 파싱, 일정 제목 부분 일치 연결
4. 수면: 기상·취침 기록, 시각 수정·삭제, 4시 기준 귀속, 지난밤 수면 시간 및 주간 평균
5. 설정: 하루 시작 시각(0~6), #wake / #sleep / #write / #add 주소 복사 및 iPhone 단축어 안내

## 사용자 요청과 별도로 제안하는 점

### 잠금화면 1회 기록: 서버 없는 PWA로는 신뢰성 보장 불가
Safari의 단축어 URL 실행 환경과 홈 화면에 설치한 iOS PWA의 localStorage는 서로 분리될 수 있음
잠금화면에서 `#wake`나 `#sleep`을 열어 저장하더라도, 홈 화면 PWA에서 그 기록을 볼 수 있다고 가정하면 안 됨
이번 시안은 URL 진입 후 '지금 기록하기' 확인 동작을 제공하되, **기기 간 또는 Safari↔PWA 자동 연동 완료 기능으로 표시하지 않음**

**권장안 A (장기)**: Supabase Edge Function에 인증된 iPhone 단축어의 'URL 내용 가져오기' POST를 보내 수면 시각을 기록하고, PWA도 동일 서버에서 읽기
단축어에 장기 비밀키를 평문으로 박아 넣는 방식은 피하고, 개인용 토큰의 보관·회수·속도 제한을 설계할 것
비용 0원과 접근 제어는 무료 플랜 정책과 사용량 검증 후 확정

**권장안 B (서버 없이 비교 시안)**: iPhone 단축어가 iCloud Drive의 로그 파일에 줄을 추가하고, PWA에서는 파일을 수동 가져오기
자동 반영/실시간 동기화가 아니고 사용자 단계가 필요하지만 웹 저장소 분리 위험을 피함
단축어의 '일어났어요/잘게요' 동작은 잠금화면에서 빠르게 실행 가능

### 시간 및 통계 제약
- 하루 시작 시각은 수면·일기 귀속용, 일정의 실제 시작 시간은 바꾸지 않음
- 4시 전 취침은 전날의 로그에 귀속
- 취침과 이후 기상이 연결될 때만 수면 시간 계산, 24시간 넘는 간격은 제외
- 요일 평균 기상 시각은 현재 단순 산술 평균, 밤샘 등 자정 경계가 많은 경우 순환 평균 등 고도화 검토
- 과거 수면 기록을 수정하면 `local_date`를 재계산
- 하루 시작 시각을 설정에서 변경할 경우 기존 `local_date` 일괄 재계산은 아직 미구현 — 데이터 이관 규칙 확정 필요

### 목표-일정 연결의 제한
- 제목의 문자열 포함으로 연결: '저녁 러닝'과 '러닝' 일치
- 동명이의어나 과거 목표명 변경으로 잘못 연결될 수 있으므로, 최종 통합 단계에 `goal_id` 명시적 연결을 추천
- 일정 종료 시간 이후 '했나요?'를 보여줄 뿐 자동 체크하지 않음

### 사용자 입력의 안전
- 자동 유형 판정은 제안일 뿐, 사용자가 변경 가능
- 목표 입력은 '주 3회 러닝', '일주일에 2번 수영' 형태를 우선 지원
- 더 다양한 문장·시간대 표현은 독립 비교 후 규칙 개선
